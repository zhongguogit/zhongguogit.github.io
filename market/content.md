# 市场数据：分类、商品种子、文案模板

## 一、为什么按「工具」分类，而不是按「提示词类型」分类

买家的真实问题是「**我手上就装了豆包，你能帮我干成什么**」，不是「你有没有写角色的提示词」。
所以一级分类按**平台**切，二级按**任务**切。同一个任务（比如「把小说改成短剧分镜」）
在豆包、扣子、千问上的写法完全不同——这正好构成三份独立商品，而不是一份商品标三个标签。

| 平台 | 它真正擅长的 | 卖家该卖什么 |
|---|---|---|
| **豆包** | 语音对话、口语理解、长文改写、生活常识 | 一句话口令（说出来的，不是打出来的） |
| **扣子 Coze** | 工作流编排、插件、定时任务、Bot 上线 | 可导入的 Bot / 工作流方案 + 配置说明 |
| **通义千问** | 超长文档、表格、代码、结构化 JSON | 长提示词模板 + 输出格式约束 |
| **AI 智能体** | 多步任务、工具调用 | 任务包（含步骤、判据、失败兜底） |
| **语音口令** | 移动场景、双手不方便时 | 可直接朗读的口令卡 |
| **Skill 包** | 给 Agent 装能力 | 符合规范的 skill 目录 + 校验脚本 |

---

## 二、双层商品结构（关键设计）

每个商品都拆成两层，这是它**能卖钱**的核心：

1. **免费层（Lite）**：一段可复制的提示词 / 一个场景说明。让人立刻用上、立刻见效。
2. **付费层（Pro）**：完整包（多场景变体 + 参数表 + 失败兜底 + 示例输入输出 + 可导入文件）。

免费层不是阉割版，是**能独立跑通的最小完整版**。
买家试完发现「确实有用，但每次都手改参数太麻烦」——这才是付费理由。
只给半句话的诱饵式免费层，退款率会高到你不想做。

## 四、卖家上架必须填的 8 个字段（少一个就不让上）

1. 标题（≤28 字，含平台名）
2. 分类
3. 价格
4. 免费层正文（≥80 字，必须能独立跑通）
5. 付费层包含项（逐条列，不许写「更多惊喜」）
6. **适用版本**（例如「豆包 App 2026.09 版实测」）
7. **失败案例**（这个提示词在什么情况下会失效——这一栏最容易建立信任）
8. 退款承诺（默认 7 天，可加严不可放宽）

## 五、平台抽成 3% 的结算口径

- 抽成基数 = **实际成交额**，不含退款单
- 3% 从卖家应收里扣，买家看到的就是标价，不额外加价
- 账单每月 1 号生成，卖家后台可导出 CSV
- 未满 ¥50 顺延，不是不给
- 争议单：买家举证 → 平台先垫付退款 → 再和卖家结算时抵扣
