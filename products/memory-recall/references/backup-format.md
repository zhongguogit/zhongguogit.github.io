# 备份文件格式与三种粒度

> "强大的压缩备份功能"具体长什么样，这一份说清楚。

---

## 一、为什么要三种粒度

| 场景 | 需要的备份 | 为什么 |
|---|---|---|
| 每周例行 | **快照**（全量） | 一次打包，放心 |
| 每次录入后 | **增量**（只存新增） | 不用每次全量，省时间 |
| 换设备 / 发给别人 | **纯特征**（只有标签） | 几 KB，不泄原文 |

---

## 二、快照格式（全量）

### 2.1 文件结构

```json
{
  "saved_at": "2026-10-18T15:30:00",
  "version": "0.1.0",
  "memories": [
    {
      "id": "M-20261018-001",
      "at": "2026-10-18T15:12:00",
      "title": "老周代发",
      "L1": "跟老周谈定厨房用品代发，佣金8个点，月底前上架……",
      "L2": "与老周谈定厨房用品代发，佣金8%，月底前上架",
      "L3": ["老周", "锅具", "谈定", "8%", "上架"],
      "level": "重要",
      "bytes": 2848
    }
  ],
  "trash": []
}
```

### 2.2 命令

```bash
python mem.py backup                          # 存到 ~/.memory-recall/snapshots/snap-20261018-153000.json
python mem.py backup --out /path/to/dir       # 存到指定位置
```

### 2.3 体积参考

| 记忆条数 | L1 原文总量 | 快照体积 |
|---|---|---|
| 10 条 | ~10 KB | ~12 KB |
| 100 条 | ~100 KB | ~115 KB |
| 1000 条 | ~1 MB | ~1.1 MB |

> 快照不压缩（JSON 直接存）。1000 条时建议 `--out` 到网盘同步目录，或加 `gzip`。

## 三、增量格式（只存新增）

### 3.1 文件结构

```json
{
  "since": "2026-10-01T00:00:00",
  "until": "2026-10-18T15:30:00",
  "added": [ /* 同 memories 结构 */ ],
  "removed_ids": ["M-20261005-007"]
}
```

### 3.2 用途

- 每次 `add` 后追加一行到 `incremental.log`；
- 恢复时可"只补新增"（不覆盖现有）；
- 冲突处理：**以 id 为准，同 id 保留较新的 `at`**。

---

## 四、纯特征格式（只有目录）

### 4.1 文件结构

```json
{
  "exported_at": "2026-10-18T15:30:00",
  "count": 12,
  "items": [
    {"id": "M-20261018-001", "at": "2026-10-18", "L3": ["老周", "8%"], "level": "重要"},
    {"id": "M-20261005-007", "at": "2026-10-05", "L3": ["老周", "12元"], "level": "一般"}
  ]
}
```

### 4.2 用途

- **换设备先带走目录**：新设备上能"找得到"，只是点开没原文；
- **发给别人做参考**：只暴露"我跟老周谈过代发，8 个点"，不暴露聊天原文；
- **体积约为主数据的 3%**：1000 条 ≈ 30 KB。

---

## 五、恢复（三种模式）

### 5.1 合并恢复（默认，最安全）

```bash
python mem.py restore snap-20261018-153000.json
```
```
📦 快照：snap-20261018-153000.json
   快照内 12 条，当前 8 条，可恢复 4 条
⬆️ 加 --yes 执行恢复（只补缺失，不覆盖现有）
```

**规则**：只补 `id` 不存在的，**绝不覆盖**现有条目。这条规则保证"恢复旧备份"不会把新记的东西冲掉。

### 5.2 按特征恢复

```
用户：只恢复老周那几条
```

从快照里筛 `L3` 含 `老周` 的，走合并恢复。

### 5.3 整体回滚（危险）

```
用户：回到 10 月 18 日的样子
```

**必须**：
1. 先自动备份当前状态（`backup --out before-rollback.json`）；
2. 列出"将丢失的条目"（当前有、快照没有的）；
3. 要求输入确认短语；
4. 回滚后再 `backup` 一次。

> v0.1 未实现整体回滚，只能手动删 + 合并恢复。这是有意的保守。

## 六、自动备份策略（建议）

| 触发 | 动作 |
|---|---|
| 每次 `add` | 追加增量日志（不生成完整快照） |
| 每 7 天首次启动 | 自动快照，保留最近 4 个 |
| 每次 `rm` 前 | 自动快照到 `snapshots/before-delete-*.json` |
| 每次 `purge` 前 | 强制要求先 `backup` |

**保留策略**：最多留 10 个快照，超出的删最旧的（但 `before-delete` 类保留最近 2 个）。

## 七、换设备怎么搬

```bash
# 老设备
python mem.py backup --out ./搬家.json
# 把 搬家.json 拷到 U 盘 / 网盘 / 发给自己

# 新设备
python mem.py restore ./搬家.json --yes
```

如果不方便拷大文件，先搬"纯特征"：

```bash
python mem.py export --tags-only --out ./目录.json    # 30 KB
```
新设备能搜到条目，原文缺；等方便时再补全量。

---

## 八、安全边界

- 备份文件是**明文 JSON**。里面有聊天原文、金额、人名；
- **不要发到公开群**；
- 上传网盘前建议自己加密（`zip -e`）；
- 本 skill **不上传任何服务器**——备份文件在你自己手上；
- 删除的记忆**不进快照**（`trash` 单独存，且 `purge` 后快照里也没有）。
