# 20 种"我记不清了"的检索策略

> 用户从来不会精准地说出要找什么。这一份是"他怎么说，我怎么找"的对照表。

---

## 一、先判断他是哪种"记不清"

| 类型 | 典型原话 | 他手上还剩什么 |
|---|---|---|
| A 只剩人名 | "那个姓周的" | 一个模糊称呼 |
| B 只剩金额 | "那个八毛钱的""十二块那个" | 一个数字 |
| C 只剩时间 | "上个月那事""过年前" | 一个时间段 |
| D 只剩场景 | "就是那次在仓库吵起来的" | 一个画面 |
| E 只剩情绪 | "那个让我很烦的事" | 一种感觉 |
| F 什么都不剩 | "我记得我记过" | 只有"记过"这件事 |

**策略**：A–E 直接搜；F 不搜，改为**给他看最近 10 条**，让他认。

## 二、20 种说法 → 怎么找

### A 类：只剩人名

| # | 用户说 | 怎么找 |
|---|---|---|
| 1 | "那个姓周的" | 模糊搜姓氏：`find 周`，命中老周/周总/周老板 |
| 2 | "老周那个事" | 精确 + 别名全展开 |
| 3 | "义乌那个老板" | 先搜地点标签，再从结果里认人 |
| 4 | "上次跟谁谈锅来着" | 搜品类「锅具」，把人名挑出来反问他 |

### B 类：只剩金额

| # | 用户说 | 怎么找 |
|---|---|---|
| 5 | "那个八毛钱的" | 搜 `8` + 别名「8%」「8元」，注意"八毛"可能是 `0.8` |
| 6 | "十二块那个" | 搜 `12元`，同时模糊搜 `12` |
| 7 | "八千那笔" | 搜 `8000元`、`八千` |
| 8 | "八九个点吧" | 区间搜：`8%` / `9%` 都列出来 |

### C 类：只剩时间

| # | 用户说 | 怎么找 |
|---|---|---|
| 9 | "上个月" | 按 `at` 字段过滤上月区间，倒序列出 |
| 10 | "过年前" | 模糊区间（±45 天），按"重要"优先排 |
| 11 | "就是刚开始那会儿" | 取**最早 5 条**，让他认 |
| 12 | "最近那次" | 直接给最近 3 条，不用搜 |

### D 类：只剩场景

| # | 用户说 | 怎么找 |
|---|---|---|
| 13 | "在仓库吵起来那次" | 搜地点「仓库」+ 情绪词反查原文 |
| 14 | "他发了一张照片那次" | 搜「照片/图/发我/看了下」 |
| 15 | "说好又反悔那次" | 搜 `谈定` + `违约/反悔/不算` 组合 |

### E 类：只剩情绪

| # | 用户说 | 怎么找 |
|---|---|---|
| 16 | "让我很烦的那个" | 搜抱怨类词：「烦/拖/催/一直/又」，按命中数排 |
| 17 | "我担心的那个" | 搜「怕/风险/万一/要是」，优先 `卡住` 事件 |
| 18 | "当时觉得挺值的" | 搜「划算/值/不错/可以」，优先含金额的条目 |

### F 类：什么都不剩

| # | 用户说 | 怎么找 |
|---|---|---|
| 19 | "我记得我记过" | 给最近 10 条（`list` 截断），让他认 |
| 20 | "就那个…算了" | 主动问**一个问题**："大概跟谁有关？" 只问一个 |

## 三、检索结果必须带的四件东西

只给条目 = 给了一堆碎片。必须给：

### 3.1 时间线

```
📌 串起来看：9 月底认识 → 10 月初报价 → 10 月中谈定代发
```

**怎么生成**：命中结果按 `at` 升序，取每条 L2 摘要的前 8 字，用 `→` 连起来。超过 5 条只取首尾 + 中间最重要的一条。

### 3.2 当前卡点

```
现在卡在：质检报告（M-20261018-002 提到）
```

**怎么生成**：在所有命中条目里找带 `卡住` 事件标签的、或含「还没/没下来/等/差」的句子，取最新一条。

### 3.3 涉及金额汇总（如果有）

```
涉及金额：12 元/件 × 500 件 = 6000 元（M-20261005-007）
```

### 3.4 下一步提示

```
⬆️ 回复「show M-20261018-001」看原文 ｜ 换个词再找 ｜ 删掉这些
```

## 四、找不到的时候（三步，不许瞎编）

### 第一步：说清我试过什么

```
🔎 「XX」没找到。
   我试过：人名别名 / 事件标签 / 摘要 / 原文模糊
```

### 第二步：给出可能的原因

```
   → 可能：① 当时没记 ② 用的是别的词（同义：YY / ZZ）
```

**禁止**：编一条"大概是这样的"给用户。记忆类工具编造内容是最严重的失信——用户会照着假记忆去做决策。

### 第三步：给一个具体动作，不是"你再想想"

```
   → 建议：告诉我大概是什么时候的事，或跟谁有关，我用时间/人名兜一圈
```

## 五、检索优先级（性能与准确度）

命中顺序，从快到慢：

1. **L3 标签精确匹配**（毫秒级，最准）
2. **L2 摘要包含**（快，覆盖度好）
3. **L1 原文包含**（慢，但不会漏）
4. **别名展开重跑一遍**（只在前三步都无命中时做）

```python
def _match(m, q):
    q2 = ALIAS.get(q, q)
    hay = m["L1"] + " " + m["L2"] + " " + " ".join(m["L3"])
    return q2 in hay or q in hay
```

> 现在的实现是"一次性扫全部"，几百条以内没问题。条目过千后应加倒排索引（L3 标签 → 条目 id 列表）。

## 六、常见误判

| 情况 | 别这么做 | 应该这么做 |
|---|---|---|
| 用户说"上次" | 别猜具体哪天 | 直接给最近 3 条让他认 |
| 用户说了一个人名但没命中 | 别改口说"可能记错了" | 说"这个名字我没存过"，然后按时间兜一圈 |
| 命中 20 条以上 | 别全部倒出来 | 只给最近 5 条 + 时间线 + "还有 15 条，要看吗" |
| 用户要的是"结论"不是"记录" | 别把 5 条摘要都贴一遍 | 一句话给结论 + 引用编号 |
