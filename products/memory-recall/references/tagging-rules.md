# 标签体系与同义词合并表

> 找不找得到，90% 取决于打标签。这一份是"说出特征就能找到"的底层规则。

---

## 一、为什么必须打三层标签

只用关键词搜原文，会有三个问题：

1. **词不一样就找不到**——你记的是"周总"，当时录的是"老周"；
2. **原文太长搜不完**——3000 字聊天记录里搜"8个点"，命中十几次，全是噪音；
3. **搜出来是一堆碎片**——你真正想要的是"这事走到哪一步了"。

三层标签解决的就是第 1、2 点；时间线（见 `recall-playbook.md`）解决第 3 点。

---

## 二、三类标签（缺一不可）

### 2.1 实体标签 ENTITY

**谁 / 什么东西 / 在哪**。

| 子类 | 例子 | 说明 |
|---|---|---|
| 人名 | 老周、老陈、安娜 | 只要是"人"，一律打 |
| 公司/店铺 | 义乌恒达、老陈的五金店 | 带"公司/厂/店/工作室"后缀自动识别 |
| 品类 | 锅具、五金、宠物用品 | 越宽越好，不要打"304 不锈钢 20cm 汤锅"这种超细的 |
| 地点 | 杭州、义乌、广州仓 | 只打"能发货/能见面"的地点 |
| 平台 | 1688、拼多多、抖音小店 | 平台名一律算实体 |

> **反例**：把"红色""大号""新款"打成实体。这些是属性，不是实体，打了只会污染检索。

### 2.2 数字标签 NUMBER

**钱 / 比例 / 数量 / 时间**。这是最有价值的一类——人回忆时最常说的就是"那个八毛钱的""那次十二元的"。

| 子类 | 原文 | 归一化后 |
|---|---|---|
| 比例 | 8个点 / 百分之八 / 8% | `8%` |
| 单价 | 12元/件 / 一件12块 | `12元` |
| 总量 | 500件 / 五千个 | `500件` |
| 时间点 | 10月18 / 10-18 | `10-18` |
| 期限 | 月底前 / 三天内 | `月底` / `3天` |
| 金额 | 八千 / 8000块 | `8000元` |

> 归一化是为了**同一件事的十种说法只占一个标签位**。

### 2.3 事件标签 EVENT

**发生了什么**。用动词，不用形容词。

```
谈定  报价  起订  打样  寄样  下单  付款  发货  到货
上架  卡住  延期  催  退款  退货  签约  承诺  违约  结清
```

事件标签决定了**能不能串出时间线**。没有事件标签，只能给一堆平行条目。

## 三、同义词合并表（核心）

### 3.1 人名

| 说法 | 归一为 |
|---|---|
| 老周 / 周总 / 周老板 / 周哥 / 周先生 | `老周` |
| 老陈 / 陈总 / 陈老板 | `老陈` |
| 安娜 / Anna / 安小姐 | `安娜` |

> **规则**：先出现的那个当主词。用户第一次说"周总"，之后主词就是"周总"，别名表跟着改。

### 3.2 金额比例

| 说法 | 归一为 |
|---|---|
| 8个点 / 8 个点 / 百分之八 / 8% / 八个点 | `8%` |
| 八千 / 8000 / 8千 / 八千块 | `8000元` |
| 十二元 / 12块 / 12元/件 | `12元` |

### 3.3 品类（宽标签）

| 说法 | 归一为 |
|---|---|
| 锅 / 炒锅 / 汤锅 / 不粘锅 / 厨房用品 | `锅具` |
| 五金 / 螺丝 / 铰链 / 合页 | `五金` |
| 宠物 / 猫砂 / 狗粮 | `宠物用品` |

> **宽标签原则**：宁可打到"锅具"，不要打到"28cm 麦饭石不粘炒锅"。
> 因为人回忆的时候只会说"那个锅的事"，不会说"那个 28cm 麦饭石的事"。

### 3.4 事件

| 说法 | 归一为 |
|---|---|
| 谈好了 / 定下来 / 敲定 / 说定了 | `谈定` |
| 问了价 / 报了个价 / 多少钱 | `报价` |
| 卡住了 / 走不下去 / 停在这 | `卡住` |
| 催了 / 又问了 / 一直问 | `催` |
| 拖了 / 往后推 / 来不及 | `延期` |

## 四、自动打标签的实现

见 `scripts/mem.py` 的 `tag()`：

```python
ENTITIES = ["老周", "周总", "周老板", "厨房用品", "锅具", "锅", "供应商", "杭州", "老陈", "安娜"]
EVENTS   = ["谈定", "报价", "卡住", "交付", "退款", "承诺", "下单", "发货", "上架", "签约"]

def tag(text):
    t = set()
    for w in ENTITIES:
        if w in text: t.add(ALIAS.get(w, w))          # 命中实体 → 归一
    for w in EVENTS:
        if w in text: t.add(w)                        # 命中事件
    for m in re.findall(r"\d+(?:\.\d+)?\s*(?:个点|%|元|块|万|件|天|月|号)", text):
        t.add(m.replace("个点", "%").replace(" ", "")) # 数字归一
    for m in re.findall(r"\d{1,2}[月\-/]\d{1,2}", text):
        t.add(m)                                      # 日期
    return sorted(t)
```

**扩充方法**：把新的人名/品类加进 `ENTITIES`，把新说法加进 `ALIAS` 即可，不用改逻辑。

## 五、标签打歪了怎么办

| 症状 | 修法 |
|---|---|
| 一条记忆没有任何标签 | 录入时补一句"这是跟 XX 关于 XX 的事"，重打 |
| 标签太多（>10 个） | 砍掉属性类，只留实体/数字/事件 |
| 同一个人出现两个标签 | 加进 `ALIAS`，然后对存量数据跑一次批量归一 |
| 检索命中太多（同义词太宽） | 不是标签问题，是**查询词**问题 → 用 `timeline` 而不是 `find` |

## 六、标签不做什么

- **不打情绪标签**（"很烦""气死了"）——情绪会误导排序，且人会变；
- **不打评价标签**（"靠谱""不靠谱"）——这是判断，不是事实；
- **不打隐私细节**（身份证号、银行卡号、家庭住址门牌）——录进来了也建议删掉这几个字段。

> 标签是"检索钥匙"，不是"内容摘要"。摘要另有 L2 层负责。
